## 用户确认的约束

- 详细文档统一放在 `docs/`，建立可持续更新的项目记忆，避免每次从头通读。
- 允许适度拆分 Python 文件与模块化，代码保持简单、职责清楚。
- 原 Webhook 是阿里云 ACR 专用，路由统一使用 `/payload_acr`。
- Docker 构建使用 Dockerfile 即可，部署内容全部交给 Docker Compose。
- 部署参数直接写在 `docker-compose.yml`，不使用额外环境文件或配置模板。
- 用户负责将项目推送 Git，阿里云 ACR 自动根据 Dockerfile 构建；后续每次修改代码不要主动尝试本地 Docker 构建。初次重构已经完成的构建与容器验证见开发进度。
- 运行环境是家中 NAS；NAS 侧 FRPC 连接公网服务器 FRPS，公网同机 Nginx 做反向代理和 HTTPS 终止。应用容器保持 HTTP 12082，证书由公网 Nginx 管理。
- FRP 代理类型、FRPC 运行方式及容器网络未知；不要擅自把应用宿主端口仅绑定到 127.0.0.1，不要假定不同容器能通过各自的 localhost 互访。公网域名与 FRP/Nginx 配置应由实际环境确认。

## 当前设计与兼容边界

- 保留 `main:app` 与 `python main.py` 开发入口，实际组装在 `app.create_app`。
- 配置由 `Settings.from_env()` 集中读取，通过应用 state 注入，便于隔离测试。
- `app/acr.py` 只解析和格式化，`app/meow.py` 只对接外部推送，`app/routes/` 只处理接口。
- `requests` 是同步客户端；手动通知用同步路由，异步 ACR 路由使用线程池，不能直接在事件循环中调用阻塞推送。
- 删除旧 ACR 路由；后续不要随意加旧别名，否则会偏离这次统一命名的要求。
- 保留原 `/health`、手动通知、可选 secret、MeoW 返回结构与 ACR HTTP 200 行为。`ok` 不代表手机收件成功。
- ACR 原有宽松请求体行为保留，同时对内层 null/错误类型兜底，防止 `.get()` 崩溃。
- 不做数据存储、任务重试、事件去重或镜像自动部署；这些是新功能，需要单独设计接口行为。
- 推送日志不记录完整请求正文、MeoW 账号端点或密钥；Uvicorn 访问日志仍可能含调用 URL 的查询参数。

## Docker 约定

- Dockerfile 仅打包运行环境和代码，不加应用 CMD、ENTRYPOINT、EXPOSE、HEALTHCHECK 或运行期挂载。
- Compose 引用现成镜像，不引入 `build:`；启动命令等运行设置都在 Compose。
- 原 ACR 基础镜像与应用镜像地址保留。`BASE_IMAGE` 构建参数提供公开 Python 3.10 替换方案。原 ACR 基础镜像本次检查为 amd64；macOS 拉取令牌协议错误可用单次命令 `GODEBUG=http2client=0` 规避，未修改持久 Docker 设置。
- Compose 服务键 `path-scanner` 是历史名称，为已有部署兼容保留；容器名仍是 `harmonyos-msg-push`。
- 原程序不用 `/data`，已移除无关 NAS 挂载，不删除宿主目录。
- 镜像地址、端口与 `environment` 值直接写在 Compose 中；MeoW 昵称默认保留原占位值 `XXXX`，部署时由用户填写。不要再引入环境文件模板或 `${...}` 插值配置。
- requirements.txt 固定运行依赖及间接依赖，requirements-dev.txt 另加测试 httpx。升级依赖后运行 Python 回归，镜像构建仍交给 ACR；本地构建须由用户另行要求。
- 依赖版本可用性以 ACR 日志为重要证据，不能用本机安装成功代替云端确认。2026-10-21 云端找不到 `fastapi==0.156.4`、候选仅至 `0.156.2`，因此改锁 `0.156.2`；其他依赖保持不变。排查先做目标 Python/平台的 `pip download` 和接口回归，不主动构建 Docker，也不因 pip 升级提示就认定其为失败原因。

## 修改后的收尾

- 更新受影响的接口/部署/源码索引文档。
- 在开发进度中写明日期、变更、命令、结果、限制与待办，不把本地模拟测试写成生产部署或真实手机收件。
- 接口或调用链变更运行 unittest，Compose 修改默认只执行 `docker compose config --quiet`。不主动打包 Docker 或运行容器测试；用户后续明确要求验证时再执行。
- 验证时使用 fake 账号和模拟 MeoW，不向真实账号发送测试通知。
- 不主动 commit、push、发布镜像或替换线上容器；这些操作需要用户的发布指令。
- 若变更稳定设计决策，再同步本文。优先阅读这些项目内记录，避免重复全量探索。
