# 接口说明

基地址示例：`http://localhost:12082`。交互文档：`/docs`，OpenAPI：`/openapi.json`。

## 路径与鉴权

| 方法 | 路径 | 用途 | secret 校验 |
| --- | --- | --- | --- |
| GET | `/health` | 服务健康检查 | 无 |
| GET | `/notify` | 查询参数手动通知 | 按配置启用 |
| POST | `/notify` | JSON 手动通知 | 按配置启用 |
| POST | `/payload_acr` | 阿里云 ACR Webhook | 按配置启用 |
| POST | `/payload_codex` | Codex 本轮处理完成通知 | 按配置启用 |

设置非空 `WEBHOOK_SECRET` 后，所有通知接口都必须附带匹配的 `?secret=...`，缺少或错误返回 `401 {"detail":"secret invalid"}`。密钥是查询参数，不从 JSON 或 Header 读取。值含特殊字符时要 URL 编码。空密钥表示保持原来的免鉴权行为。

旧的 ACR 路径已经移除，不提供别名或重定向。升级时必须同步调整 ACR 控制台 Webhook 和相关反向代理路径。

## 健康检查

```bash
curl --noproxy '*' http://localhost:12082/health
```

响应示例：

```json
{"ok": true, "nickname": "你的昵称", "api_base": "https://api.chuckfang.com"}
```

这仅表示应用能响应，不验证 MeoW 连通性或手机收件。

## 手动通知

GET 查询参数：

| 参数 | 要求 | 行为 |
| --- | --- | --- |
| `msg` | 必填 | 缺少时返回 422；保留原来允许空查询字符串的行为 |
| `title` | 可选 | 缺省或空时用 `DEFAULT_TITLE` |
| `nickname` | 可选 | 缺省或空时用 `MIAO_NICKNAME` |
| `url` | 可选 | 缺省或空时用 `DEFAULT_JUMP_URL`，仍为空则不发送该字段 |
| `secret` | 按配置 | 共享密钥 |

```bash
curl --get 'http://localhost:12082/notify' \
  --data-urlencode 'msg=测试通知' \
  --data-urlencode 'title=ACR测试' \
  --data-urlencode 'secret=替换为你的密钥'
```

POST 使用 JSON 对象，字段同 GET；`secret` 仍放在 URL 中。`msg` 缺少、为 null 或空字符串时返回 `400 {"detail":"msg is required"}`。保留原有对 `title`、`msg` 的字符串转换行为。

```bash
curl -X POST 'http://localhost:12082/notify?secret=替换为URL编码后的密钥' \
  -H 'Content-Type: application/json' \
  -d '{"title":"测试标题","msg":"测试内容","url":"https://example.com"}'
```

## ACR Webhook

在阿里云控制台设置：

```text
https://your-server.example/payload_acr?secret=替换为URL编码后的密钥
```

请求体示例（用于说明当前代码识别的字段，不表示所有 ACR 版本都必定提供这些字段）：

```json
{
  "repository": {
    "repo_full_name": "team/app",
    "namespace": "team",
    "name": "app",
    "region": "cn-shanghai"
  },
  "push_data": {
    "tag": "v1",
    "digest": "sha256:example",
    "pushed_at": "2026-10-21 12:00:00"
  }
}
```

格式化结果：

```text
镜像自动构建完成: team/app:v1
仓库：team/app
区域：cn-shanghai
Tag：v1
Digest：sha256:example
时间：2026-10-21 12:00:00
```

`repo_full_name` 缺少时用 `namespace/name`；没有 tag 时标题显示 `latest`，正文不补 Tag。不存在的字段不显示，时间按来源值原样展示。默认跳转地址优先使用 `DEFAULT_JUMP_URL`，否则沿用仓库全名（它可能不是完整 URL）。

保留原有的宽松接收行为：空报文、非 JSON、非对象 JSON，或 `push_data` / `repository` 类型错误时仍生成兜底通知，正文为“收到 ACR 推送”。标题沿用原文案，不据此判定实际构建状态，也不执行镜像部署。

## Codex 本轮处理完成通知

```text
POST /payload_codex
Content-Type: application/json
```

本接口接收未来电脑端脚本转发的 Codex `notify` JSON，保留官方字段的连字符命名，不要求转换另一套结构。第一版只发送 `agent-turn-complete` 的通知。官方字段参考 [OpenAI Docs：Notifications](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications)；`device-name` 是本服务接收的自定义扩展，不是官方字段。

“本轮处理完成”只表示收到该轮事件，不表示业务任务成功、测试通过、所有排队消息处理完毕或整个窗口空闲。本服务仅整理和截取输入及最后回答的原文，不生成新的语义摘要，也不据回答另行推断成功/失败状态。

### 请求字段

| 字段 | 要求 | 用途 |
| --- | --- | --- |
| `type` | 必填非空字符串，纯空白也无效 | 事件类型，精确匹配 `agent-turn-complete` 才发送 |
| `thread-id` | 可选字符串或 null | 会话 ID，仅用于应用日志 |
| `turn-id` | 可选字符串或 null | 轮次 ID，仅用于应用日志 |
| `cwd` | 可选字符串或 null | 提取最后一级项目目录名 |
| `input-messages` | 可选字符串数组或 null | 按顺序合并为任务简述，数组元素必须是字符串 |
| `last-assistant-message` | 可选字符串或 null | 最后一条助手回答的原文摘录 |
| `device-name` | 可选字符串或 null，自定义扩展 | 提供时显示设备，不从 IP 或 User-Agent 推断 |

除 `type` 外，字段缺失或 null 按无内容处理；空白字符串和空数组也有对应兜底。未知字段被忽略，数字和布尔值不会自动转成字符串。`nickname`、`url`、`title` 等未知字段不能覆盖服务端配置；接收账号始终使用 `MIAO_NICKNAME`。下划线名称不是连字符字段的替代名。

### 本地测试 curl

以下示例面向本地测试服务。自动测试全部 mock MeoW；手动执行 curl 时服务仍会按配置发送通知，因此本地测试应使用模拟 MeoW 服务及 fake 账号。**对真实部署执行该请求会发送实际通知。** 本次没有执行此 curl，也没有安装电脑端发送脚本。

本地配置 `WEBHOOK_SECRET` 为空时可直接运行；非空时，在 URL 上追加正确且经过 URL 编码的 `?secret=...`：

```bash
curl --noproxy '*' --request POST 'http://127.0.0.1:12082/payload_codex' \
  --header 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "type": "agent-turn-complete",
  "thread-id": "thread-example",
  "turn-id": "turn-example",
  "cwd": "/Users/mack/projects/reviewx-server",
  "input-messages": [
    "修复筛选条件联动问题，并执行相关测试"
  ],
  "last-assistant-message": "已修复筛选条件联动问题，相关测试通过。",
  "device-name": "Mac"
}
JSON
```

### 手机通知格式

标题：`Codex 本轮完成 · reviewx-server`。

```text
设备：Mac
项目：reviewx-server
任务：修复筛选条件联动问题，并执行相关测试
回答：已修复筛选条件联动问题，相关测试通过。
接收时间：2026-10-21 18:30:00 +08:00
```

- 项目名兼容 `/`、反斜杠及末尾分隔符，仅提取末级名称，不输出 `cwd` 完整路径。空路径、根目录、只有 Windows 盘符或 `.` / `..` 时显示“未知项目”。
- 设备名有实际内容时才显示；设备及任务中的连续空白整理为单个空格。空白输入消息被过滤，多条消息按原顺序用空格合并，无任务内容则省略该行。
- 回答统一换行、清理首尾及行尾空白，保留正文换行和行内原文；无内容时显示“本轮处理已结束，未提供回答正文”。示例中的“相关测试通过”来自请求原文，本服务不另行确认这一结论。
- 任务摘录最多 120 个字符，回答摘录最多 800 个字符，整个标题最多 80 个字符；超出时以一个 `…` 结尾，总长度包含该省略号，按 Python 字符串字符数计算。这些值集中在 `app/codex.py` 的常量中，无新增环境变量。
- 接收时间由服务端在格式化时生成，固定 UTC+08:00，格式为 `YYYY-MM-DD HH:MM:SS +08:00`；不接受请求覆盖，不当作 Codex 精确完成时间，不计算耗时。
- 会话/轮次 ID 不进入手机正文，不用路径或 ID 拼接链接。仅当配置了 `DEFAULT_JUMP_URL` 时发送该 `url`，未配置则省略。

仅有 `{"type":"agent-turn-complete"}` 时也发送兜底通知，标题为 `Codex 本轮完成 · 未知项目`，正文包含项目、兜底回答和接收时间。

### 响应与异常

支持的事件完成格式化并执行一次 MeoW 调用后，返回 HTTP 200：

```json
{
  "ok": true,
  "meow_result": {
    "http_status": 200,
    "resp": {"示例": "实际 MeoW 响应"}
  }
}
```

`meow_result` 原样复用 `push_meow` 的结果结构。这里 HTTP 200 和 `ok: true` 只表示请求已处理，**不能视为 MeoW 业务成功或手机收件成功**。客户端必须继续检查 `meow_result.http_status` 和 `meow_result.resp` 中的 MeoW 业务响应。下游非 2xx（例如 503）及 HTTP 200 中的业务失败信息如实保留；超时或连接异常保留为 `{"http_status":0,"error":"异常信息"}`。不伪造推送成功，不自动重试。

合法但暂不支持的事件类型返回 HTTP 200，不调用 MeoW，不发送兜底手机通知：

```json
{"ok": true, "ignored": true, "reason": "unsupported event type"}
```

事件类型精确匹配，不自动去掉两侧空白后改判为支持事件。非 JSON、非对象 JSON、无效编码、缺少 `type`、空白 `type`、已知字段类型错误返回 HTTP 422，并且不调用 MeoW；即使事件类型暂不支持，也先验证这些字段类型。`detail` 数组包含错误位置和说明，不回显输入正文或校验上下文。

鉴权复用已有 `verify_secret`：配置了密钥但缺少或不匹配时返回 401，不推送，JSON 中的 `secret` 无效；空密钥不要求传参。异步路由读取/校验 JSON 后把同步网络请求放入线程池，推送等待期间健康检查仍可响应。新增应用日志只记录事件类型、会话/轮次 ID、忽略标记和下游 HTTP 状态，不打印原始请求、任务/回答、设备、账号端点或密钥。

没有数据库、历史、自动摘要、重试、去重或队列监控。同一事件重复提交会再次推送。后续电脑端仅需转发官方 notify JSON，按需补上 `device-name` 和查询参数密钥，并按上述规则检查响应；本次不配置 `~/.codex/config.toml`，不开发或安装本地发送脚本，不接入 Hooks 或 App Server。

## 推送结果与异常

手动通知响应示例：

```json
{"http_status":200,"resp":{"示例":"MeoW原始JSON响应"}}
```

ACR 响应示例：

```json
{
  "ok": true,
  "meow_result": {"http_status": 200, "resp": {"示例":"MeoW原始JSON响应"}},
  "user_agent": "请求中的User-Agent"
}
```

推送使用 `POST <MIAO_API_BASE>/<编码后的昵称>`，JSON 包含 `title`、`msg` 和可选 `url`，请求超时参数为 10 秒。MeoW 返回 JSON 时透传解析后的结果，非 JSON 时用 `{"text":"原文"}` 封装。HTTP 非 2xx 不转换成本服务的 5xx；连接、超时或响应 JSON 解析异常时返回 `{"http_status":0,"error":"异常信息"}`。

ACR 的 HTTP 200 与 `ok: true` 仅表示完成本次处理，推送是否成功要继续检查 `meow_result.http_status` 和 MeoW 的业务响应。此契约沿用原项目，没有自动重试与幂等去重；重复 Webhook 可能产生重复通知。
