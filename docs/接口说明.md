# 接口说明

基地址示例：`http://localhost:12082`。交互文档：`/docs`，OpenAPI：`/openapi.json`。

## 路径与鉴权

| 方法 | 路径 | 用途 | secret 校验 |
| --- | --- | --- | --- |
| GET | `/health` | 服务健康检查 | 无 |
| GET | `/notify` | 查询参数手动通知 | 按配置启用 |
| POST | `/notify` | JSON 手动通知 | 按配置启用 |
| POST | `/payload_acr` | 阿里云 ACR Webhook | 按配置启用 |

设置非空 `WEBHOOK_SECRET` 后，三个通知接口都必须附带匹配的 `?secret=...`，缺少或错误返回 `401 {"detail":"secret invalid"}`。密钥是查询参数，不从 JSON 或 Header 读取。值含特殊字符时要 URL 编码。空密钥表示保持原来的免鉴权行为。

旧的 ACR 路径已经移除，不提供别名或重定向。升级时必须同步调整 ACR 控制台 Webhook 和相关反向代理路径。

## 健康检查

```bash
curl --noproxy '*' http://localhost:12082/health
```

响应示例：

```json
{"ok": true, "nickname": "你的昵称", "api_base": "https://api.chuckfang.com"}
```

这仅表示应用能响应，不验证 MeoW 连通性或手机收件。

## 手动通知

GET 查询参数：

| 参数 | 要求 | 行为 |
| --- | --- | --- |
| `msg` | 必填 | 缺少时返回 422；保留原来允许空查询字符串的行为 |
| `title` | 可选 | 缺省或空时用 `DEFAULT_TITLE` |
| `nickname` | 可选 | 缺省或空时用 `MIAO_NICKNAME` |
| `url` | 可选 | 缺省或空时用 `DEFAULT_JUMP_URL`，仍为空则不发送该字段 |
| `secret` | 按配置 | 共享密钥 |

```bash
curl --get 'http://localhost:12082/notify' \
  --data-urlencode 'msg=测试通知' \
  --data-urlencode 'title=ACR测试' \
  --data-urlencode 'secret=替换为你的密钥'
```

POST 使用 JSON 对象，字段同 GET；`secret` 仍放在 URL 中。`msg` 缺少、为 null 或空字符串时返回 `400 {"detail":"msg is required"}`。保留原有对 `title`、`msg` 的字符串转换行为。

```bash
curl -X POST 'http://localhost:12082/notify?secret=替换为URL编码后的密钥' \
  -H 'Content-Type: application/json' \
  -d '{"title":"测试标题","msg":"测试内容","url":"https://example.com"}'
```

## ACR Webhook

在阿里云控制台设置：

```text
https://your-server.example/payload_acr?secret=替换为URL编码后的密钥
```

请求体示例（用于说明当前代码识别的字段，不表示所有 ACR 版本都必定提供这些字段）：

```json
{
  "repository": {
    "repo_full_name": "team/app",
    "namespace": "team",
    "name": "app",
    "region": "cn-shanghai"
  },
  "push_data": {
    "tag": "v1",
    "digest": "sha256:example",
    "pushed_at": "2026-10-21 12:00:00"
  }
}
```

格式化结果：

```text
镜像自动构建完成: team/app:v1
仓库：team/app
区域：cn-shanghai
Tag：v1
Digest：sha256:example
时间：2026-10-21 12:00:00
```

`repo_full_name` 缺少时用 `namespace/name`；没有 tag 时标题显示 `latest`，正文不补 Tag。不存在的字段不显示，时间按来源值原样展示。默认跳转地址优先使用 `DEFAULT_JUMP_URL`，否则沿用仓库全名（它可能不是完整 URL）。

保留原有的宽松接收行为：空报文、非 JSON、非对象 JSON，或 `push_data` / `repository` 类型错误时仍生成兜底通知，正文为“收到 ACR 推送”。标题沿用原文案，不据此判定实际构建状态，也不执行镜像部署。

## 推送结果与异常

手动通知响应示例：

```json
{"http_status":200,"resp":{"示例":"MeoW原始JSON响应"}}
```

ACR 响应示例：

```json
{
  "ok": true,
  "meow_result": {"http_status": 200, "resp": {"示例":"MeoW原始JSON响应"}},
  "user_agent": "请求中的User-Agent"
}
```

推送使用 `POST <MIAO_API_BASE>/<编码后的昵称>`，JSON 包含 `title`、`msg` 和可选 `url`，请求超时参数为 10 秒。MeoW 返回 JSON 时透传解析后的结果，非 JSON 时用 `{"text":"原文"}` 封装。HTTP 非 2xx 不转换成本服务的 5xx；连接、超时或响应 JSON 解析异常时返回 `{"http_status":0,"error":"异常信息"}`。

ACR 的 HTTP 200 与 `ok: true` 仅表示完成本次处理，推送是否成功要继续检查 `meow_result.http_status` 和 MeoW 的业务响应。此契约沿用原项目，没有自动重试与幂等去重；重复 Webhook 可能产生重复通知。
